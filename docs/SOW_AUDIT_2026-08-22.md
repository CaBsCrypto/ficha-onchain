## Hallazgos corregidos

- document-soulbound no compilaba en tests: unwrap sobre valores ya desenvueltos por el cliente Soroban, errores sin try_* y fixture con lifetime incorrecto. Se corrigieron los tests, sin alterar lógica del contrato.
- CI omitía esa suite y conservaba instrucciones WASM antiguas. Se prueban ahora cuatro contratos más E2E y se usa stellar contract build.
- CI de aplicación ahora incluye npm test.
- README, contracts/README, docs/CONTRACTS y AGENTS.md se alinearon. Se conserva la sección previamente añadida a AGENTS.md.
- El script recuperado no propagaba fallos y tenía un problema de invocación npm en Windows. Ahora emite logs y results.json y retorna un exit code no cero si falla un check solicitado.
- No se repiten los conteos antiguos de vulnerabilidades como resultado actual: no se ejecutó npm audit en esta revisión.

## Reproducibilidad

Desde la raíz, con dependencias instaladas:

~~~sh
node scripts/audit-sow.mjs --verify --contracts --build
~~~

Produce [results.json](evidence/sow-2026-09-05/results.json) y logs por check. El build usa un snapshot aislado bajo .next/sow-build-* sin .env ni credenciales heredadas, con Turbopack predeterminado; descarga fuentes Google. Solo se amplía la raíz de resolución del snapshot para incluir node_modules enlazado. No certifica un despliegue de Vercel. Los tests Rust usan --offline --locked y requieren la caché Cargo disponible.

Instalación: npm ci --offline --no-audit --no-fund usa caché npm local; si faltan tarballs, resolverlos desde registro con permiso de red. No modificar el lockfile para eludir errores.
