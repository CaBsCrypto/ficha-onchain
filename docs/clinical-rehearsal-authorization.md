## Scoped runner and historical reconciliation

The runner is `scripts/run-clinical-rehearsal-authorization.mjs`:

- `--once` requires an approved live local manifest before connecting. It does not enqueue. It acquires filesystem signer locks for administrator and relayer, direct PostgreSQL source locks for both, and the existing booking-worker compatibility lock. Other pending administrative, booking, prescription or clinical attempts block execution. It processes the selected UUID, persists its signed envelope before its single send, then reads the receipt. If that UUID already has a saved transaction hash, a valid `--once` invocation only reconciles it and cannot resend.
- `--reconcile` may validate an expired approved scope at a historical valid inspection instant solely to verify its same saved envelope and receipt. For schema 1 that is the original creation instant; for schema 2 it is the later of the pinned approval instant and `notBefore`. Approval pins, manifest correspondence and the fixed original dates remain required. Preparation, signing and submission callbacks are independently forbidden and the signer is not instantiated. It may update the selected request's SQL confirmation from the matching receipt. It cannot create an authorization, replacement hash or queue item. Historical receipt verification does not require today's registry executable to equal the earlier executable; the stored envelope, signatures, receipt and expected authorization record checks remain in force.

Both modes load local configuration silently, accept no credentials or authority selectors on the command line, and never change environment files. No mode is executed automatically. Browser enrollment, signatures and Testnet submission require the separately approved exact scope.
